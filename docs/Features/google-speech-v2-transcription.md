# Resumable Google Cloud Speech-to-Text V2

Applications with durable ingestion can use `GoogleSpeechV2TranscriptionProvider` to turn one audio or video recording into timed transcript segments. It sends the original track container to the official Google Speech V2 SDK through an existing private Cloud Storage bucket managed by `ManagedCode.Storage`. Every segment with spoken text includes the first and last recognized word offsets from the original recording.

## Configuration

Supply `GoogleSpeechV2TranscriptionOptions` with the numeric project number in `ProjectId`, an explicit `Location`, a supported Speech V2 `Model` and `LanguageCode`, an existing private `BucketName`, and an authorized `GoogleCredential`. Bind the operation to those approved settings throughout its lifetime. For Ukrainian, Google lists `uk-UA` with model `long` in the `eu` and `us` locations. Choose a bucket location that meets the same residency requirements. [Google's supported models and languages](https://docs.cloud.google.com/speech-to-text/docs/speech-to-text-supported-languages) · [Google regional and locational endpoints](https://docs.cloud.google.com/docs/security/compliance/restrict-endpoint-usage)

The credential used by MarkItDown needs Speech recognition and operation get, list and cancel access in the Speech project and staging object create, get and delete permissions in the bucket. Google Speech reads staged media through the project's Speech-to-Text service agent. A bucket in a different project needs an explicit grant for that agent. [Google's batch access requirements](https://docs.cloud.google.com/speech-to-text/docs/batch-recognize#enable-access-to-cloud-storage)

Google detects the audio codec itself. Supported inputs include WAV, FLAC, MP3, Ogg Opus, WebM with Opus, and MP4/M4A/MOV with supported AAC. Google enforces the codec and duration limits. Batch accepts up to eight hours per file, while `chirp_3` supports word timestamps for only up to 20 minutes. [Google's supported decoding formats](https://docs.cloud.google.com/speech-to-text/docs/reference/rest/v2/projects.locations.recognizers#AutoDetectDecodingConfig) · [Speech quotas](https://docs.cloud.google.com/speech-to-text/docs/quotas) · [Chirp 3 limits](https://docs.cloud.google.com/speech-to-text/docs/models/chirp-3)

## Operation lifecycle

1. Call `CreateInputReference` with the accepted command ID, the verified SHA-256 of the immutable recording version, and its container metadata. Persist the returned reference before moving bytes. The reference later identifies the exact object to clean up if staging is interrupted.
2. Call `StageAsync` with that reference and the same verified original recording from its beginning. Reopening and retrying that same immutable version targets the same object. A different SHA-256 targets a different object. Stay with the original staged reference throughout the command.
3. Call `StartAsync` once and persist its returned operation, including the provider-assigned name. The SDK makes a single submission attempt. If the response is lost, call `FindOperationAsync` with the same staged input. It reads Speech V2 operations from the configured project and location and matches the full Cloud Storage URI in the original Google request. Persist a single match as the operation. An empty listing can mean delayed visibility, so keep the attempt unresolved through the application's recovery deadline. Multiple matching operations fail closed. A second submission can create another billable Google operation. [Google Speech V2 operation listing](https://docs.cloud.google.com/speech-to-text/docs/operations) · [Google operation metadata](https://docs.cloud.google.com/speech-to-text/docs/reference/rest/v2/OperationMetadata)
4. Call `ReadAsync` with the persisted operation. Each call reads one observation. `Processed` supplies the result, with zero segments for a successful recording containing no recognized speech. Provider failures surface a safe code, and any recognized speech without valid word offsets returns `Failed`.
5. For cancellation, call `CancelAsync`, then read until a terminal state. Call `DeleteStagedAsync` after recording the terminal result durably or after conclusively determining the source was never submitted. Deleting a missing staging object succeeds. A bucket lifecycle rule can limit retention of objects left after an unresolved submission. Google Cloud Storage soft-delete and retention settings determine when deleted bytes become unrecoverable. [Google's operation cancellation](https://docs.cloud.google.com/speech-to-text/docs/reference/rest/v2/projects.locations.operations/cancel) · [Google Cloud Storage soft delete](https://docs.cloud.google.com/storage/docs/soft-delete)
